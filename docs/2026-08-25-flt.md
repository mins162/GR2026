## 1. FLT가 바꾸는 것

기존 DAG 라우팅은 DAG의 두 노드를 잇는 wire가 **한 층에서 시작해 같은 층에서 끝나야** 한다.
FLT는 edge 도중 **층 변경 1회**를 허용해, 양 끝 층이 다른 연결을 가능하게 한다.

DP 비용식이 바뀌는 지점은 한 곳뿐이다 (논문 Fig. 10) :

```
기존 : a_l = cost(A, l) + wireCost(A→B, l)
FLT  : a_l = min_i ( cost(A, i) + edgeCost(A→B, i→l) )
```

`edgeCost(u→v, i→l)` 는 batch마다 GPU에서 미리 채우는 lookup table이다 (Algorithm 3) :
edge를 등간격으로 보간한 후보점 p마다 `wire(u→p, i) + via(p, i→l) + wire(p→v, l)` 를 계산해
최솟값과 그때의 층 변경 지점을 저장한다.

## 2. 코드에 이미 있던 자리

`src/Lshape_route_detour.hpp` 에 원저자가 남긴 미사용 선언·할당이 그대로 있었다 :

```cpp
__managed__ double *cost_edges;   // = edgeCost
__managed__ int *best_change;     // = changePoint
cudaMalloc(&cost_edges, parent_cnt_estimate * 81 * sizeof(double));
```

`81 = 9 × 9` = **층 쌍 개수** (ISPD24는 GPU 측 `L = 9`). 즉 레이아웃까지 FLT용으로 이미 잡혀 있고
커널만 비어 있었다. 그대로 채워 썼으므로 **GPU 메모리 추가 소비는 0**.

## 3. 구현

| 위치 | 내용 |
| --- | --- |
| `flt_edge_precompute()` | Algorithm 3. 스레드 1개 = (DAG edge, 도착층) 1쌍, 그 도착층의 열 전체를 채움 |
| `flt_best_incoming_cost()` | 위 DP식의 `min_i`. **DP와 traceback이 같은 함수를 호출** |
| `Lshape_route_node_cuda()` | 부모로 올려보내는 비용을 `wireCost` → `flt_best_incoming_cost` 로 교체 |
| `get_routing_tree_cuda()` | 층 변경이 있으면 wire 2개 + 변경 지점 via 1개를 emit |

설계상 짚어둘 점 :

- **후보점은 내부점만.** 끝점을 후보로 두면 그 노드가 어차피 찍는 via 스택과 중복 계상된다.
  간격은 논문대로 `max(⌊k/20⌋, 1)` (k = edge가 지나는 G-cell 수) → edge당 최대 19개
- **대각(i = l)은 기존 단일층 wire 식을 그대로** 써서, 층 변경을 한 번도 고르지 않으면
  pre-FLT 해와 정확히 같아지게 했다. 스위치 off 검증이 의미를 가지는 근거
- **시작층은 저장하지 않고 traceback에서 재계산.** `costs[]`·`cost_edges[]` 는 bottom-up과
  traceback 사이에 바뀌지 않으므로 같은 min을 다시 돌리면 반드시 같은 답이 나온다.
  덕분에 배열 2개(시작층 전파용)를 통째로 안 만들었다
- **층 방향 제약** : edge는 축 정렬이므로 시작층·도착층 모두 edge 방향과 preferred direction이
  맞아야 한다 → 두 층은 **같은 parity**, 즉 층 변경은 2층 단위로 뛴다

### route 버퍼

traceback이 edge당 wire 1개 → 최대 wire 2개 + via 1개로 늘어나는데 `routes[]` 에는 bound check가 없다.
넷당 예산은 `ROUTE_PER_PIN = 27` ints/pin. 실측용 커널을 넣어 매 FLT 런이 아래를 찍게 했다 :

```
Stage 2 FLT: fullest net used 56.4% of its route buffer (budget 27 ints per pin)
```

56.4% → 1.77배 여유. 넘치면 100%를 넘겨 찍히므로 다른 벤치마크에서 위험해지면 바로 드러난다.

- on 쪽 score도 precompute 커널을 갈아엎는 동안 396,641,195 ~ 396,642,446 (폭 1,250) 안에서만
  움직임 — 부동소수 합산 순서 차이일 뿐, 선택되는 경로는 동일
- 위 표는 **같은 바이너리·연속 실행**한 off/on 한 쌍이라 하드웨어·빌드 변수가 없음.
  단 −1,018,428 은 노이즈(±3,650)의 279배라 개별 런 1회로도 유의

## 5. 런타임 — 증가분의 귀속과 precompute 최적화

### 어디서 늘었나

`INSTANTGR_AUGMENTED_DAG_PROFILE=1`로 off/on을 같은 조건에서 분해 (프로파일 sync가 들어가
절대값은 clean 런보다 큼) :

| 구간 | FLT off | FLT on (최종) | 차이 |
| --- | ---: | ---: | ---: |
| remove+cost | 2.583 s | 2.413 s | 노이즈 |
| **flt precompute** | 0 | **3.546 s** | **+3.55 s (~72%)** |
| **bottom-up DP** | 2.912 s | 4.281 s | **+1.37 s (~28%)** — 층 열거 O(L)→O(L²)의 본질 비용 |
| traceback | 0.222 s | 0.272 s | +0.05 s |
| commit | 5.578 s | 5.076 s | 노이즈 |

bottom-up의 +47%는 DP가 edge마다 (시작, 도착) 쌍 ~20개의 lookup을 더 읽는 대가로,
논문이 "DP가 이미 O(L²)라 복잡도 불변"이라 한 항목이다. 알고리즘 고유 비용이라 그대로 두고,
**precompute를 공격**했다.

### precompute 최적화 과정 — 시도 6개 중 3개만 살아남음

전부 같은 벤치마크·프로파일 조건, score는 매번 evaluator로 품질 보존 확인 :

| 버전 | 구조 | precompute | 교훈 |
| --- | --- | ---: | --- |
| v1 | 스레드=(edge, 도착층), 시작층→점 순서 | 9.66 s | via를 시작층마다 재읽음 |
| v2 | 〃, 점→시작층 재배치 (via prefix 공유) | 4.58 s | 읽기 −45% → 시간 −53% |
| v3 | 스레드=node 1개가 전 쌍 처리, 배열 `best[5][5]` | 9.46 s | 스레드 10↓ + 로컬 배열이 L1 밀어냄 — **회귀** |
| v4 | v3 구조 + 도착층 스레드 복원, 배열 유지 | (launch 실패) | **130 reg × 512 > 64K — 런치가 조용히 실패.** `__launch_bounds__` 필수 |
| v4' | 〃 + launch bound (126 reg) | 7.19 s | 점유율 33%로 반토막 — 배열의 동적 인덱싱이 원인 |
| v5 | 배열 제거, 스칼라 2-pass (64 reg) | 5.52 s | 점유율 복구, 그래도 v2보다 느림 |
| **v6** | **스레드=(edge, 도착층)를 par_id로 직접 인덱싱** | **3.55 s** | **straggler 제거 — 채택** |
| v7 | v6 + 도착층 기준 양방향 sweep (pass1 제거) | 3.99 s | 스레드별 루프 경계 발산이 더 손해 — **되돌림** |

핵심 발견 두 개 :

- **straggler** : node당 스레드를 배정하면 그 스레드가 자기 node의 incoming edge를 전부 순회한다.
  parent 수 분포가 치우쳐 있어 소수 스레드가 배치의 꼬리 시간을 결정했다. 역매핑은 공짜로 있었다 —
  `currentChildIDX[par_id]/10`이 바로 그 edge의 child node라, 스레드를 edge로 직접 인덱싱하면
  스레드당 작업이 후보점 ≤19개로 균일해진다 (v2 → v6, −23%)
- **레지스터가 점유율을 지배** : `aidx` 동적 인덱싱이 있는 5-원소 배열들은 전부 레지스터에
  상주해서 130 reg까지 부풀고, SM당 스레드가 1/3로 준다. 출력 열(`best[5]/bp[5]`)만 남기고
  스칼라로 풀어야 64 reg / 점유율 66%가 나온다. 130 reg × 512-스레드 블록은 아예 **런치가
  조용히 실패**하며(에러 체크 없음), FLT가 no-op이 된 채 score만 이상해진다 —
  `__launch_bounds__(THREAD_NUM)`이 이를 컴파일 타임에 막는다

이 서버의 `ncu`는 GPU 카운터 권한(ERR_NVGPUCTRPERM, root 필요)이 없어 하드웨어 프로파일은
불가 — 위는 전부 A/B 실측으로 판별했다.

### 결과

- clean 런 : `mempool_group` +5.73s (+15.7%) → **+4.38s (+11.9%)**, `bsg_chip` +6.1% → **+4.7%**
- 논문은 edge precompute를 augmented routing의 22%로 보고 — 우리 최종은 S2 GPU 프로파일의 22.7%로 일치

## 6. 기본값을 off로 둔 이유

이 리포지토리의 목표는 README대로 **더 빠른** global routing이고, 지금까지 넣은 최적화는 전부
품질 무변화 + 속도 개선이었다. FLT는 방향이 반대다 (품질 −0.256% / 속도 +11.9%).
켜고 끄는 판단은 쓰는 쪽에 남기는 게 맞다고 보고 `INSTANTGR_FLT=1` opt-in으로 뒀다.
