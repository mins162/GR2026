## 1. FLT가 바꾸는 것

기존 DAG 라우팅은 DAG의 두 노드를 잇는 wire가 **한 층에서 시작해 같은 층에서 끝나야** 한다.
FLT는 edge 도중 **층 변경 1회**를 허용해, 양 끝 층이 다른 연결을 가능하게 한다.

DP 비용식이 바뀌는 지점은 한 곳뿐이다 (논문 Fig. 10) :

```
기존 : a_l = cost(A, l) + wireCost(A→B, l)
FLT  : a_l = min_i ( cost(A, i) + edgeCost(A→B, i→l) )
```

`edgeCost(u→v, i→l)` 는 batch마다 GPU에서 미리 채우는 lookup table이다 (Algorithm 3) :
edge를 등간격으로 보간한 후보점 p마다 `wire(u→p, i) + via(p, i→l) + wire(p→v, l)` 를 계산해
최솟값과 그때의 층 변경 지점을 저장한다.

## 2. 코드에 이미 있던 자리

`src/Lshape_route_detour.hpp` 에 원저자가 남긴 미사용 선언·할당이 그대로 있었다 :

```cpp
__managed__ double *cost_edges;   // = edgeCost
__managed__ int *best_change;     // = changePoint
cudaMalloc(&cost_edges, parent_cnt_estimate * 81 * sizeof(double));
```

`81 = 9 × 9` = **층 쌍 개수** (ISPD24는 GPU 측 `L = 9`). 즉 레이아웃까지 FLT용으로 이미 잡혀 있고
커널만 비어 있었다. 그대로 채워 썼으므로 **GPU 메모리 추가 소비는 0**.

## 3. 구현

| 위치 | 내용 |
| --- | --- |
| `flt_edge_precompute()` | Algorithm 3. 스레드 1개 = (DAG edge, 도착층) 1쌍, 그 도착층의 열 전체를 채움 |
| `flt_best_incoming_cost()` | 위 DP식의 `min_i`. **DP와 traceback이 같은 함수를 호출** |
| `Lshape_route_node_cuda()` | 부모로 올려보내는 비용을 `wireCost` → `flt_best_incoming_cost` 로 교체 |
| `get_routing_tree_cuda()` | 층 변경이 있으면 wire 2개 + 변경 지점 via 1개를 emit |

설계상 짚어둘 점 :

- **후보점은 내부점만.** 끝점을 후보로 두면 그 노드가 어차피 찍는 via 스택과 중복 계상된다.
  간격은 논문대로 `max(⌊k/20⌋, 1)` (k = edge가 지나는 G-cell 수) → edge당 최대 19개
- **대각(i = l)은 기존 단일층 wire 식을 그대로** 써서, 층 변경을 한 번도 고르지 않으면
  pre-FLT 해와 정확히 같아지게 했다. 스위치 off 검증이 의미를 가지는 근거
- **시작층은 저장하지 않고 traceback에서 재계산.** `costs[]`·`cost_edges[]` 는 bottom-up과
  traceback 사이에 바뀌지 않으므로 같은 min을 다시 돌리면 반드시 같은 답이 나온다.
  덕분에 배열 2개(시작층 전파용)를 통째로 안 만들었다
- **층 방향 제약** : edge는 축 정렬이므로 시작층·도착층 모두 edge 방향과 preferred direction이
  맞아야 한다 → 두 층은 **같은 parity**, 즉 층 변경은 2층 단위로 뛴다

### route 버퍼

traceback이 edge당 wire 1개 → 최대 wire 2개 + via 1개로 늘어나는데 `routes[]` 에는 bound check가 없다.
넷당 예산은 `ROUTE_PER_PIN = 27` ints/pin. 실측용 커널을 넣어 매 FLT 런이 아래를 찍게 했다 :

```
Stage 2 FLT: fullest net used 56.4% of its route buffer (budget 27 ints per pin)
```

56.4% → 1.77배 여유. 넘치면 100%를 넘겨 찍히므로 다른 벤치마크에서 위험해지면 바로 드러난다.

## 4. 결과 — `mempool_group`

같은 바이너리 `run/InstantGR.flt`, 스위치만 토글. 로그 : `run/logs-flt/`

| 항목 | FLT off | FLT on | 차이 |
| --- | ---: | ---: | ---: |
| wirelength cost | 260,161,160 | 260,079,586 | −81,574 (−0.031%) |
| via cost | 71,305,104 | 71,525,264 | **+220,160 (+0.309%)** |
| overflow cost | 66,191,590 | 65,037,092 | **−1,154,497 (−1.744%)** |
| **total cost** | **397,657,854** | **396,641,942** | **−1,015,912 (−0.256%)** |
| open / incompleted | 0 / 0 | 0 / 0 | — |
| **total runtime** | **36.59 s** | **42.32 s** | **+5.73 s (+15.7%)** |

- 개선분이 전부 overflow에서 나오고 via가 늘어난 것은 FLT의 동작 그대로다 —
  혼잡 구간을 층을 갈아타며 피하고, 그 대가로 via를 더 쓴다
- **off 경로 무변화 확인** : off 런 3회가 397,656,351 (pre-FLT 바이너리) / 397,660,001 / 397,657,854,
  폭 3,650 으로 [08-25 재측정](2026-08-25-rtx3060-remeasure.md) §1의 런간 흔들림과 같은 자릿수.
  DP·traceback 수정이 off 경로를 건드리지 않았다는 뜻. 런타임도 36.03 / 35.71 / 36.59s
- 위 표는 **같은 바이너리·연속 실행**한 off/on 한 쌍이라 하드웨어·빌드 변수가 없음.
  단 −1,015,912 는 노이즈(±3,650)의 278배라 개별 런 1회로도 유의

## 5. 런타임 — edge precompute가 값을 다 쓴다

`INSTANTGR_AUGMENTED_DAG_PROFILE=1` 기준 (단계별 sync가 들어가 절대값은 clean 런보다 큼) :

| 구간 | 1차 구현 | 점 루프 재배치 후 |
| --- | ---: | ---: |
| remove+cost | 2.462 s (11.4%) | 2.437 s (14.7%) |
| **flt precompute** | **9.660 s (44.5%)** | **4.579 s (27.6%)** |
| bottom-up DP | 4.299 s (19.8%) | 4.246 s (25.6%) |
| traceback | 0.286 s (1.3%) | 0.281 s (1.7%) |
| commit | 4.979 s (23.0%) | 5.019 s (30.3%) |
| 합계 | 21.687 s | 16.563 s |

1차 구현은 (시작층 → 후보점) 순서로 돌아서 후보점 하나의 via 비용을 시작층마다 다시 읽었다.
**후보점을 바깥 루프로** 돌리면 그 점의 via 프리픽스를 시작층 전부가 공유한다 (같은 parity라 2층씩 누적).
후보점당 global read가 약 26회 → 14회로 줄어 **precompute −53%**, clean 런 46.42s → 42.32s.

- 논문은 edge precompute를 augmented routing의 22% / 전체의 7.1%로 보고 — 재배치 후 27.6%로 근접
- bottom-up DP는 층 열거가 O(L) → O(L²)가 됐는데도 4.30 → 4.25s로 사실상 불변.
  논문이 "DP가 이미 O(L²)라 복잡도 불변"이라 한 부분이 실측으로 확인됨

## 6. 기본값을 off로 둔 이유

이 리포지토리의 목표는 README대로 **더 빠른** global routing이고, 지금까지 넣은 최적화는 전부
품질 무변화 + 속도 개선이었다. FLT는 방향이 반대다 (품질 −0.256% / 속도 +15.7%).
켜고 끄는 판단은 쓰는 쪽에 남기는 게 맞다고 보고 `INSTANTGR_FLT=1` opt-in으로 뒀다.
